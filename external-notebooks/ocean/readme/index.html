Ocean Datacube Hackathon

This repository contains information and guided notebooks about the Ocean Hackathon. The core aspects of the hackathon are:

  1. Marine datasets covering the Mediterranean Sea and the global ocean from ESA-funded science projects, hosted on object storage.

  2. A Mediterranean Sea datacube with a common spatial grid and separate stores for monthly, hourly, and daily data.

  3. Guided notebooks that show how to access the cloud-hosted datasets, convert data into cloud-native formats, combine them into analysis-ready datacubes, and use those collections in scientific workflows.

  4. Information about creating a local environment to work in, or using the provided cloud platform.

EarthCODE Context¶

The hackathon is supported by EarthCODE, and the data is available through EarthCODE’s Open Science Catalog.

2. ESA Mediterranean Sea Datacube¶

The ESA Mediterranean Sea Datacube combines marine datasets on a common 1/24° EPSG:4326 grid. The data are available in four online GeoZarr stores with different time and depth coordinates:

StoreContentsCube coordinate coverage
ocean-med-monthly-cube.zarr4DMED PFT/Kd, ocean heat content, OceanSODA, BICEP, and MITHOMonthly, January 2016–December 2022
hourly_cube.zarrWOC and CMEMS current components at 15 mHourly, 30 December 2014–30 December 2019
ocean-med-biophysics.zarr4DMED primary production and 3D physical fields at 18 depths, 3–135 mDaily, 1 January 2016–31 July 2022
ocean-med-daily-surface-cube.zarr4DMED salinity/density, FSLE, both 4DVarNet reconstructions, and CAREHeat categoriesDaily, 1 January 2016–31 December 2022

The notebooks open these online stores directly over HTTPS using consolidated metadata. An internet connection is required; only the selected chunks are read. Group 0 is full resolution; groups 1 and 2 contain spatial summaries at 1/6° and 1/3°. Individual products may cover only part of a store’s time axis.

Start with cube access and example plots, then explore building a local cube from two datasets and time series at every depth. The overview lists source products, OSC links, variables, licences, and how the data were combined.

3. File Formats and Metadata¶

The format notebooks show 1) how datasets can be transformed in cloud-optimised formats, and 2) described with metadata.

Note: the examples we used for these notebooks come from Polar studies, since they came in different file formats.

Dataset Formats¶

FormatBest forWhy it matters in object storage
ZarrLabelled multidimensional arraysChunked reads allow an analysis to load only the required variables, regions, depths, and times.
Cloud Optimized GeoTIFF (COG)Individual rasters or raster stacksInternal tiling and overviews support efficient range reads and quicklooks.
GeoParquetVector geometries and tabular observationsColumnar storage enables efficient filtering and carries standard geospatial metadata.

See the notebooks in 3_File_formats_and_metadata/ and the Cloud-Native Geospatial Guide for more detail.

Metadata¶

Rich metadata makes each collection easier to find, interpret, cite, and reuse. Collection metadata should document provenance, licence, variables, units, spatial and temporal extent, processing history, and access assets.

EarthCODE collections use the SpatioTemporal Asset Catalog (STAC) specification to provide a consistent, machine-readable description of geospatial data.

4. Visualisation¶

Most of the datasets are part of one of the cubes, which in turn can be interactively visualised since they are in geozarr format. To open the visualisation click the “Explore Data” link in the ntoebooks, or go directly to the visualisation website . The site wraps a simple GeoZarr viewer and can be replaced with a compatible GeoZarr in any programming language or tool. Suggested Hackathon Workflow¶

  1. Pick a science question, user workflow, or define your own.

  2. Browse the dataset catalogue and open the relevant access notebooks.

  3. Use the existing collections to answer the question.

  4. Use the file-format notebooks as guidance when preparing a new dataset to add to the existing collections.

  5. Put your code in 5_Hackathon_Code/ and keep generated data out of Git.

  6. Submit your work as a pull request with a short description of the question, datasets, methods, and outputs.

Environment Notes¶

The notebooks assume a Python geospatial environment with common Pangeo tools. The repository’s pixi.toml and Conda environment.yml provide packages including xarray, dask, geopandas, rasterio, rioxarray, pyproj, shapely, pandas, numpy, matplotlib, and pystac.

Install the environment and start JupyterLab with Pixi:

pixi install
pixi run jupyter lab

Or with Conda:

conda env create --file environment.yml
conda activate earthcode_cubes
jupyter lab

Network access is only needed for remote object-store reads or optional source downloads. The format tutorials write generated examples to downloaded_data/, which is ignored by Git.
